# المتطلبات غير الوظيفية
## Non-Functional Requirements

### 1. مقدمة

تحدد هذه الوثيقة معايير الجودة والقيود التقنية التي يجب أن يلتزم بها نظام إدارة المبيعات والمخزون، لضمان توفير تطبيق آمن ومستقر وسهل الاستخدام وقابل للتطوير.

### 2. الأمان (Security)

- NFR-001: يجب حماية صفحات النظام من الوصول دون تسجيل الدخول.
- NFR-002: يجب تخزين كلمات المرور باستخدام خوارزميات آمنة لتجزئة كلمات المرور (Password Hashing).
- NFR-003: يجب تطبيق نظام صلاحيات يمنع المستخدم من تنفيذ العمليات غير المسموح بها.
- NFR-004: يجب التحقق من صحة البيانات على الخادم قبل حفظها.
- NFR-005: يجب حماية واجهات API من الوصول غير المصرح به.
- NFR-006: يجب استخدام اتصال HTTPS عند نشر النظام.
- NFR-007: يجب عدم تخزين كلمات المرور أو مفاتيح الاتصال الحساسة داخل مستودع GitHub.

### 3. الأداء (Performance)

- NFR-008: يجب أن تستجيب الصفحات والعمليات الاعتيادية خلال مدة مناسبة في ظروف التشغيل الطبيعية.
- NFR-009: يجب أن تكون عمليات البحث وعرض قوائم المنتجات سريعة.
- NFR-010: يجب استخدام أساليب مناسبة لجلب البيانات وتقليل الاستعلامات غير الضرورية.
- NFR-011: يجب دعم تقسيم البيانات إلى صفحات (Pagination) عند عرض القوائم الكبيرة.

### 4. سهولة الاستخدام (Usability)

- NFR-012: يجب أن تكون الواجهة واضحة وسهلة التعلم.
- NFR-013: يجب توحيد تصميم الأزرار والنماذج والقوائم.
- NFR-014: يجب إظهار رسائل واضحة عند نجاح العمليات أو فشلها.
- NFR-015: يجب توفير رسائل تحقق مفهومة عند إدخال بيانات غير صحيحة.
- NFR-016: يجب تنظيم التنقل بين وحدات النظام بطريقة منطقية.

### 5. الاستجابة للشاشات (Responsiveness)

- NFR-017: يجب أن يعمل النظام على أجهزة الكمبيوتر والأجهزة اللوحية والهواتف الذكية.
- NFR-018: يجب أن تتكيف الجداول والنماذج والقوائم مع أحجام الشاشات المختلفة.
- NFR-019: يجب المحافظة على سهولة الاستخدام دون الحاجة إلى تمرير أفقي غير ضروري على الشاشات الصغيرة.

### 6. موثوقية البيانات (Data Reliability)

- NFR-020: يجب المحافظة على تكامل العلاقات بين جداول قاعدة البيانات.
- NFR-021: يجب تنفيذ العمليات المالية وتحديث المخزون بطريقة تضمن عدم حفظ أجزاء غير مكتملة من العملية.
- NFR-022: يجب الاحتفاظ بسجل موثوق للمعاملات المؤكدة.
- NFR-023: يجب توفير آلية مناسبة للنسخ الاحتياطي واستعادة البيانات.
- NFR-024: يجب منع تكرار تنفيذ العملية الواحدة نتيجة إعادة إرسال الطلب.

### 7. قابلية الصيانة (Maintainability)

- NFR-025: يجب تقسيم التطبيق إلى وحدات مستقلة ومنظمة.
- NFR-026: يجب اتباع أسلوب موحد في تسمية الملفات والمتغيرات والدوال.
- NFR-027: يجب فصل إعدادات البيئة عن الشيفرة البرمجية.
- NFR-028: يجب توثيق واجهات API والقرارات التقنية المهمة.
- NFR-029: يجب استخدام Git لتتبع التغييرات وإدارة إصدارات المشروع.

### 8. التوافق (Compatibility)

- NFR-030: يجب أن يعمل النظام على المتصفحات الحديثة مثل Chrome وFirefox وEdge.
- NFR-031: يجب أن يدعم النظام أحجام الشاشات المختلفة.
- NFR-032: يجب أن تكون واجهات النظام متوافقة مع متطلبات الاستخدام على أجهزة الكمبيوتر والهواتف.

### 9. دعم اللغات (Localization)

- NFR-033: يجب توفير واجهة باللغة العربية والإنجليزية.
- NFR-034: يجب دعم اتجاه الكتابة من اليمين إلى اليسار RTL للعربية.
- NFR-035: يجب دعم اتجاه الكتابة من اليسار إلى اليمين LTR للإنجليزية.
- NFR-036: يجب ترجمة رسائل النظام وعناصر الواجهة في اللغتين.
- NFR-037: يجب عرض التواريخ والأرقام والعملات بطريقة مناسبة لإعدادات اللغة.

### 10. قابلية التوسع (Scalability)

- NFR-038: يجب تصميم قاعدة البيانات بطريقة تسمح بإضافة وحدات ووظائف جديدة مستقبلاً.
- NFR-039: يجب أن يسمح تنظيم التطبيق بتوسيع وظائف النظام دون الحاجة إلى إعادة بنائه بالكامل.
- NFR-040: يجب فصل الواجهة الأمامية عن الخادم وقاعدة البيانات من خلال واجهات API واضحة.

### 11. معايير القبول العامة

يعد النظام مستوفياً للمتطلبات غير الوظيفية الأساسية عندما:

1. تكون صفحات النظام محمية وفق صلاحيات المستخدمين.
2. تعمل العمليات الأساسية دون أخطاء مؤثرة.
3. تكون بيانات الفواتير والمخزون متسقة.
4. تعمل الواجهة على الشاشات المستهدفة.
5. يمكن استخدام النظام باللغتين.
6. تكون الشيفرة منظمة وقابلة للصيانة.
7. تكون بيانات النظام قابلة للنسخ الاحتياطي والاستعادة.

### 12. ملاحظات

تستخدم هذه المتطلبات كمعايير لتقييم جودة النظام أثناء التطوير والاختبار، ويمكن تحديد قياسات أداء أكثر دقة بعد تجهيز بيئة النشر والاختبار.
