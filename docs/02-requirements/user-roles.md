# أدوار المستخدمين والصلاحيات
## User Roles and Permissions

### 1. مقدمة

يحدد هذا المستند أدوار المستخدمين داخل نظام إدارة المبيعات والمخزون، والصلاحيات المتاحة لكل دور.

يهدف نظام الصلاحيات إلى حماية بيانات المتجر، وتنظيم العمليات اليومية، ومنع المستخدمين من تنفيذ عمليات خارج مسؤولياتهم.

يعتمد الإصدار الأول على ثلاثة أدوار رئيسية:

- Admin
- Cashier
- Inventory Manager

### 2. مدير النظام (Admin)

يمتلك مدير النظام جميع الصلاحيات، ويكون مسؤولاً عن إدارة النظام وإعداداته.

الصلاحيات:

- تسجيل الدخول والخروج.
- عرض لوحة التحكم.
- إضافة المنتجات وتعديلها وتعطيلها.
- إدارة التصنيفات.
- عرض وإدارة المخزون وتسوية الكميات.
- تسجيل المبيعات وإلغاء الفواتير وفق الضوابط.
- تسجيل المشتريات وإدارتها.
- إدارة العملاء والموردين.
- معالجة المرتجعات.
- عرض التقارير المالية والتشغيلية.
- إدارة المستخدمين.
- إنشاء الحسابات وتعديلها وتعطيلها.
- تحديد أدوار المستخدمين.
- تعديل إعدادات المتجر واللغة والعملة.

### 3. أمين الصندوق (Cashier)

مسؤول عن تنفيذ عمليات البيع والتعامل مع العملاء.

الصلاحيات:

- تسجيل الدخول والخروج.
- عرض لوحة تحكم مبسطة.
- البحث عن المنتجات وعرض أسعارها وكمياتها المتاحة.
- إنشاء فواتير البيع.
- إضافة المنتجات إلى الفاتورة.
- تطبيق الخصومات ضمن الحدود المسموح بها.
- تسجيل المدفوعات.
- عرض وطباعة فواتير البيع.
- البحث عن العملاء وإضافة عميل جديد.
- عرض سجل المبيعات الخاص به.
- تسجيل طلب إرجاع وفق سياسة المتجر، دون اعتماد المرتجع النهائي إلا من مستخدم مخوّل.

القيود:

- لا يستطيع إدارة المستخدمين أو الأدوار.
- لا يستطيع تعديل إعدادات المتجر.
- لا يستطيع تعديل تكلفة شراء المنتجات.
- لا يستطيع إجراء تسوية للمخزون.
- لا يستطيع حذف الفواتير المؤكدة.
- لا يستطيع الاطلاع على التقارير المالية والإدارية الحساسة.

### 4. مسؤول المخزون (Inventory Manager)

مسؤول عن المنتجات والمخزون والمشتريات.

الصلاحيات:

- تسجيل الدخول والخروج.
- عرض لوحة تحكم المخزون.
- إضافة المنتجات وتعديل بياناتها.
- إدارة التصنيفات.
- متابعة الكميات المتاحة.
- تسجيل حركات المخزون.
- إجراء تسويات المخزون ضمن الصلاحيات المحددة.
- متابعة المنتجات منخفضة المخزون.
- إضافة الموردين وتعديل بياناتهم.
- إنشاء فواتير الشراء.
- تسجيل استلام المشتريات.
- متابعة سجل المشتريات.
- مراجعة طلبات مرتجعات المشتريات.

القيود:

- لا يستطيع إدارة المستخدمين أو الأدوار.
- لا يستطيع تعديل إعدادات النظام.
- لا يستطيع اعتماد المدفوعات أو التعديلات المالية الحساسة إلا إذا مُنح صلاحية إضافية.
- لا يستطيع حذف فواتير البيع المؤكدة.
- لا يستطيع الاطلاع على التقارير المالية الحساسة.

### 5. مصفوفة الصلاحيات

| الوظيفة | Admin | Cashier | Inventory Manager |
|---|---|---|---|
| لوحة التحكم | كاملة | مبسطة | المخزون |
| إدارة المستخدمين | نعم | لا | لا |
| إدارة المنتجات | نعم | عرض فقط | نعم |
| إدارة التصنيفات | نعم | عرض فقط | نعم |
| عرض المخزون | نعم | نعم | نعم |
| تسوية المخزون | نعم | لا | نعم |
| إنشاء فاتورة بيع | نعم | نعم | لا |
| إلغاء فاتورة بيع | نعم | لا | لا |
| عرض سجل المبيعات | كامل | سجله | لا |
| إنشاء فاتورة شراء | نعم | لا | نعم |
| استلام المشتريات | نعم | لا | نعم |
| إدارة العملاء | نعم | إضافة وعرض | عرض فقط |
| إدارة الموردين | نعم | لا | نعم |
| اعتماد المرتجعات | نعم | لا | حسب نوع المرتجع |
| التقارير | كاملة | محدودة | تقارير المخزون |
| إعدادات المتجر | نعم | لا | لا |

### 6. قواعد تطبيق الصلاحيات

1. يجب التحقق من صلاحية المستخدم في الخادم (Backend)، وليس في الواجهة فقط.
2. لا يجوز للمستخدم الوصول إلى وظيفة غير مصرح بها عن طريق استدعاء API مباشرة.
3. يجب ربط كل عملية بيع أو شراء بالمستخدم الذي نفذها.
4. يجب تسجيل العمليات الحساسة في سجل حركة مناسب.
5. لا يجوز حذف السجلات المالية المؤكدة حذفاً نهائياً.
6. يمكن لمدير النظام تعديل صلاحيات المستخدمين من خلال تعيين الدور المناسب.
7. يجب رفض أي طلب لا يمتلك المستخدم صلاحية تنفيذه وإرجاع استجابة HTTP 403.

### 7. ملاحظات الإصدار الأول

- كل مستخدم يمتلك دوراً رئيسياً واحداً.
- لا يدعم الإصدار الأول إنشاء أدوار مخصصة.
- لا يدعم الإصدار الأول تحديد صلاحيات منفصلة لكل مستخدم.
- يمكن تطوير نظام صلاحيات أكثر تفصيلاً في إصدار لاحق.

### 8. الهدف من التصميم

توفير نظام صلاحيات بسيط وواضح يغطي احتياجات المتاجر الصغيرة والمتوسطة، ويحافظ على سلامة العمليات والبيانات دون تعقيد غير ضروري.
